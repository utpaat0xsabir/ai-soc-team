# AI SOC Team roadmap

Baseline 2026-11-22. See [current status](docs/project/current-status.md) for evidence and [the next five milestones](docs/project/next-milestones.md) for priority. This roadmap has no delivery-date or rollout commitments.

| Milestone and status | Scope, dependency and security prerequisites | Deliverables, verification and definition of done | Contributor roles |
|---|---|---|---|
| 1. Foundation and B4 security closure — partial, gates blocked | Existing tenant, evidence/audit, PostgreSQL and B4 tooling. Requires independent artifact, custodian, admission/freeze, monitor, fixture and migration decisions. | Verified credential-free containment, approved read-only preflight and evidence receipts. Separate Gate 2 disposition and guarded rehearsal with postconditions and recovery. Preserve scope and fail closed on uncertainty. | Linux, PostgreSQL, security reviewers |
| 2. Reliable data integrations — Wazuh implemented, rollout gated | Finish source attribution, least privilege, checkpoint integrity and approved operational rollout. Extract adapter contract and develop a second read-only SIEM connector. | Two fixture-backed adapters pass paging, idempotency, schema drift, rotation and cross-tenant tests. Live Wazuh deployment needs its separate authorization. | Connector, backend and SOC engineers |
| 3. SOC intelligence and cases — libraries implemented, cases proposed | Build persistent case/timeline layer on normalized evidence and deterministic rules. Add entity and asset enrichment, ATT&CK mapping, campaign lineage and reporting only against verified evidence. | One reproducible incident timeline with exact evidence links, deterministic grouping, benign controls and no cross-tenant joins. | Analysts, detection and backend engineers |
| 4. AI analyst team — synthetic L1 present | Add authorized local model evaluation and formal L1/L2/L3 handoffs. Depends on cases, admission, gateway and evaluation contracts. | Offline tier transition harness, deterministic fallback, checked citations, bounded budgets and zero unauthorized transitions. Review a local-only synthetic pilot separately. | AI and SOC engineers, security reviewers |
| 5. Knowledge and intelligence — proposed | Build bounded [RAG](docs/ai/rag-architecture.md), governed intelligence and incident memory. Evaluate graphs after a retrieval baseline. | Frozen dataset and reproducible metrics, proven authorization and expiry, reliable citation validation and abstention. Independently review deployment dependencies. | Retrieval, graph, model and privacy engineers |
| 6. Policy-controlled response — proposed | Requires stable cases, actor policy, approvals, receipts and verified recovery. Evaluate one no-op then one scoped SOAR adapter. | Typed action manifest, approval/expiry/replay checks, dry run, independent postcondition and denial audit. No destructive execution without a separately authorized release. | Security architects, integration engineers, responders |
| 7. Platform operations — partial tooling, rollout gated | Separate secret custody, deployment pins, logs and metrics, restore and load evidence. Build on the independently approved runtime and data boundaries. | Verified restore, independently retained checkpoints, resource isolation, bounded retries and documented recovery. Use sanitized telemetry. | Platform, database and reliability engineers |
| 8. Analyst experience — proposed, backend-first | Stable tested case, evidence and approval APIs first. Follow with workbench, timeline, graph, reports, approval queue, detection coverage, hunt workspace and metrics. | Usability and access tests for core case flows, verified tenant exports, accessible interfaces and audit links for reviewer decisions. | SOC analysts, product and frontend engineers |

Contributions can progress in parallel using synthetic fixtures. Operational activation depends on the gated prerequisites above. [Contribution guide](CONTRIBUTING.md) · [Security index](docs/README.md)
