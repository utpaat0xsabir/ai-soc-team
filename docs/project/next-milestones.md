# Next five engineering milestones

This is the prioritized slice of the [roadmap](../../ROADMAP.md). Each operational phase needs its own authorization.

1. **B4 fixture and Gate 1 readiness.** Independently verify a controlled, credential-free systemd fixture or use a disposable VM. Close admission/freeze, authenticated event coverage and backend teardown gaps. Pin the exact artifact and read-only target before requesting Gate 1. A passing fixture alone cannot satisfy the live PostgreSQL contract.
2. **B4 rehearsal and restricted data plane.** Obtain independent historical digest disposition, recovery evidence and separate Gate 2 approval. Verify staged catalogs and restricted identity reads/writes only on the authorized disposable target. Close Wazuh least-privilege and source mapping validations before scheduling a rollout.
3. **Stable connector and case contracts.** Extract a versioned normalized contract from Wazuh into a fixture-backed second SIEM adapter. Establish tenant-qualified timeline and case state. Prove idempotent partial-failure handling and correlated evidence traceability.
4. **Local analyst and retrieval evaluation.** Extend synthetic L1 evaluation, land one ATT&CK retrieval experiment, and verify formal L1/L2 handoffs offline. Measure retrieval against literal and deterministic baselines. Advance local runtime evaluation only with explicit authorization and zero security boundary regressions.
5. **Bounded investigation and response pilot.** Add synthetic L3 reports and typed action review through a no-op adapter. Require human approval and independently verified execution receipts. A separately approved live pilot follows only after denial, replay and ambiguity tests pass.

Milestones 3–5 may develop offline fixture prototypes while B4 is blocked. Live activation depends on the security prerequisites in the roadmap. Backend integrity and API stability precede user-interface commitments.
