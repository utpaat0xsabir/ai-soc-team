Once independently provisioned and explicitly authorized, the reviewed
bootstrap follows this handoff:

1. Accept only the decision ID from the requester. Resolve the record and
   exact digest via the separately authenticated channels. Validate scope,
   approval window, expiry, target, artifact inventory, isolation evidence,
   CA and budgets against the frozen environment. Refuse missing inputs.
2. Invoke the existing launcher inside that trust boundary. Reserve one use
   before startup. Establish the durable hold and containment. The trusted
   worker bootstrap supplies the two scoped secrets process-locally.
   Preserve the read-only admission deadline and separate recovery deadline.
3. After any attempt, close admission and reconcile process scope before
   backend reconciliation. Recheck the independently pinned Docker identity.
   Keep the hold if process, backend or target state is uncertain. Treat an
   uncertain release as an incident. Accept success only when the verified
   report is bound to the same decision and arrives within its window.
4. Persist a bounded canonical record through the protected sink with the
   decision and run IDs, artifact/query pins, status, sanitized failure
   code, evidence digest when verified, and teardown/hold/target outcomes.
   Hash the exact record bytes and retain the digest with the independent
   approval reference. Restrict backend identifiers to authorized
   reconciliation records. Exclude raw driver errors, credentials, DSNs
   and evidence or audit payloads. Storage failure prevents operational
   sign-off and requires separate reconciliation.
